背景很简单：我想要一个自己的博客，但没有服务器、没有域名，也没系统学过前端。最后走通了「AI 编辑器 + 免费静态托管」这条路 —— 全程零成本，网址是 `xxx.pages.dev`。

过程不算顺利。真正卡住我的不是写代码，而是下面这 5 个地方。

## 坑 1｜软件装的顺序错了

我一开始先去装 pnpm，装完发现用不了。原因是**pnpm 依赖 Node.js** —— Node 还没装好，pnpm 自然跑不起来。

**正确顺序**：Node.js → Git → pnpm → 编辑器。

这件事让我明白：装环境不是"把清单上的东西都装上"，而是**先搞清楚谁依赖谁**。

## 坑 2｜装完了，命令还是"无法识别"

Node 装完了，敲 `node -v` 却提示"不是内部或外部命令"。

两个常见原因：

1. 安装时**没勾选 "Add to PATH"**
2. 装完**没重启终端**（旧终端读的还是旧的环境变量）

**解决**：重装时把那一项勾上，或者干脆重启一次电脑。CLI 工具装完"命令找不到"，先怀疑 PATH。

## 坑 3｜下载一直超时

npm 官方源、Node 官网、GitHub 都在国外，下载经常卡住甚至超时。我遇到两种不同的情况：

- **依赖装不下来** → 把源换成国内镜像（npmmirror），速度立刻正常
- **`git clone` 卡在 0%** → 这是链路被干扰，不是仓库的问题。换手机热点，或者给 git 单独指定可用 IP、让 git 走代理，都能解决

**关键心态**：超时不等于"我做错了什么"。先区分是**源太远**还是**链路被干扰**，再对症下药。

## 坑 4｜点了 "Download ZIP"，而不是 Fork

我一开始直接点了 GitHub 页面上的 `Download ZIP`，解压出代码，看起来一切正常。

问题是：**ZIP 下来的代码和我的 GitHub 账号没有任何关联** —— 后面「推送代码 → 网站自动更新」这条流水线会直接断掉，变成每次都要手动上传。

**正确做法**：先 **Fork**（把仓库复制到自己账号下），再 `git clone` 到本地。这样「本地 → 我的仓库 → 托管平台」三者才连得起来。

## 坑 5｜托管平台的「生产分支」填错了

部署那一步，教程里写生产分支填 `main`，我照着填了。结果**推送之后线上完全没有反应**。

折腾很久才发现：**这个主题仓库的默认分支实际是 `master`**，不是 `main`。

最坑的地方在于：**填错不会报任何错**。构建照样成功，只是每次推送都进了"预览环境"，正式网址永远不更新。

> 所以现在我做这类配置，都会先确认仓库的默认分支名，而不是照抄教程。

## 最后

回头看，这 5 个坑没有一个是因为"我技术不行"，全都是**信息差**：

- 谁依赖谁
- 环境变量什么时候生效
- 网络为什么不通
- 仓库和 ZIP 的区别
- 默认分支叫什么

而它们有一句共同的解法：**把报错原文完整丢给 AI，别只发一句"报错了"**。我这次九成的卡点都是这么通的 —— 剩下那一成，是我没把信息说全。
